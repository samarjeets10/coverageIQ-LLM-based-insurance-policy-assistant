## 2. Schema Reconciliation & Security Guarantees

- **Authoritative Schema Mapping:** M5's original SQL referenced legacy `policy_versions` and `policies.(name, owner_user_id, organization_id)` with non-null defaults that risked inventing unverified policy terms. CoverageIQ reconciles `ai_service/common/tables.py` and `ai_service/recommendation/filters.py` directly against `policies`, `policy_documents`, and `policy_attributes`, filtering strictly on `policies.visibility = 'catalog'`, `policies.status = 'active'`, `policy_documents.id = policies.active_version_id`, `policy_documents.is_archived = FALSE`, `policy_documents.ingestion_status = 'completed'`, and `policy_attributes.is_catalog_eligible IS TRUE`.
- **Nullable Extracted Attributes (`NO EVIDENCE = NO CLAIM`):** Missing fields remain SQL `NULL` and are explicitly surfaced to the user in `recommended_policy.missing_attributes` and deterministic hard-filter eliminations rather than substituted with defaults.
- **Role & Tenant Isolation:** Regular consumer accounts remain restricted (`403`) from creating `visibility='catalog'` policies or toggling catalog visibility; private policies remain invisible to unrelated users both in search candidates and in `filter_report.eliminations`. Node gateway re-verifies returned recommendations and `chunk_id` citations directly against PostgreSQL before returning HTTP `200` (`502` fail-closed on forged IDs or chunks).

## 5. Issues Discovered & Resolved During Live Verification

1. **NVIDIA Nemotron reasoning token exhaustion (`total_tokens=9754, has_content=False`):** Under default `enable_thinking` + `temperature=1.0`, `nvidia/nemotron-3.5-lightning-30b-a3b` exhausted the `8192` token budget on internal reasoning while extracting structured attributes from uploaded PDFs. Resolved cleanly by supporting optional `enable_thinking=False` (`chat_template_kwargs`) and `temperature=0.0` in `NvidiaNemotronProvider` / `LLMClient`, plus sparse JSON instructions in `PolicyAttributeExtractor` — cutting live attribute extraction latency from `36.7s` / `max_tokens` failure down to `~2.6s`.
2. **Internal backfill `AuthorizedScope` trust check (`HTTP 503`):** `POST /internal/recommendations/extract-attributes` initially constructed `AuthorizedScope(...)` directly without `trusted_gateway_context=True`, causing `validate_authorized_scope` to fail closed. Switched to `AuthorizedScope.from_gateway_context(..., trusted_internal=True, allow_catalog_read=True)`.
3. **Malformed `policy_id` bypass in Node verification (`recommendationGateway.service.js`):** Filtering `UUID_RE` before checking membership allowed non-UUID IDs to skip the catalog query; updated to fail closed (`502`) on any malformed `policy_id` or document version mismatch.
4. **Migration rollback test coupling (`qa.integration.test.js`) & offline test worker LLM env:** Updated `qa.integration.test.js` down/up verification to roll back 2 steps (`1764250300000` + `1764250200000`) inside a `try/finally` recovery block and added `LLM_PROVIDER=offline` to test worker subprocesses so offline ingestion tests do not make live Nemotron calls during extraction.
